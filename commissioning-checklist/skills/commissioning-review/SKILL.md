# 投产前检查清单评审

面向 PLC 程序投产(下载到真机/交付)前的最后一道人工+agent 联合评审。流程:**逐维度过清单 → 记录证据(文件:行号/块名)→ 输出结构化报告**。任何一项拿不准,如实标注存疑交用户判断,不要替程序说好话。

## 评审前置

1. 确认评审对象版本:当前 ST/工程的验证结论只对**最后一次 `ok:true` 信封的 `stHash`** 成立;地址平移或逻辑改动后旧结论作废。
2. 仿真侧已通过 verify(尽力而为 + 上限:plan 错 2 轮、compile 3 轮封顶),未覆盖的工况如实标注。
3. 真机投产另需走完 tia-download-troubleshoot 的下载链检查(不在本清单内)。

## 维度 1:变量命名与结构

- DB 分层是否清晰:IO / Mode / Alarm / Seq / Order 各司其职,设备层指令区命名固定(Order/Step),全文搜得到指令流;
- 命名风格一致(全中文或全英文,不混);一个名字一个含义,不一物多名;
- **TIA SCL 保留字**:`counter`/`timer` 等必须 `x_` 前缀改名,且接口/body/标签表/OB 形参**全链路一致**(只改一处 = 编译错或暗坑);标识符不能以下划线结尾;
- 边沿实例(R_TRIG/F_TRIG)、定时器实例按执行器编号成组,不散落。

## 维度 2:地址分配

- 每个声明的 `%I`/`%Q`/`%IW` 都有真实硬件映射;**每个声明的 `%Q` 输出都有赋值驱动来源**(死输出编译能过、运行恒初值,是投产事故高发点);
- 模拟量标定统一在采集层做(4-20mA / PT100 每类一个缩放 FB/FC),标定系数不散落各处;
- 地址区间规划成文档(输入/输出/内部 M 区各自范围),多工位共享地址时确认无冲突;
- 地址或 AT 变量平移后:旧验证信封作废,重跑 verify 盖章。

## 维度 3:互锁与安全

- 急停/停止类信号**最先判断且压倒后续**;互斥输出真的互斥(逐个枚举验证);
- 安全门/防护类:**双反馈合成**(门锁线圈反馈 AND 位置反馈),只信一根线 = 会被未关到位的门骗过;
- 干预/解锁记录用 SR 锁存(边沿触发 + 显式赋值),**人工复位才清**,不许自动消;
- **FirstScan 单独处理**:上电时若门开/状态机在中间态,没有边沿可抓,必须首扫位补置位/复位;
- Ready 条件链六项齐全:整机 OK + 自动模式 + 无报警 + 全部原位 + 不在跑 + **NOT 完成**(漏掉「NOT 完成」会在循环边界重复触发);
- 反馈等待用「需求位旁路」(`NOT 需求 OR 反馈到位`),同一块适配带/不带该工序的配方;
- 中转层只搬不判:多模式指令管道里出现 IF/模式判断 = 两个模式指令叠加的温床;
- **边界检查** `<` vs `<=` 逐阈值过一遍,相等归哪侧写进注释;CASE 都有 ELSE;
- 安全功能(人身安全切断)由安全回路(F-CPU/安全继电器)完成——普通 PLC 程序只进允许/禁止链,评审发现程序在「替代安全功能」必须必修。

## 维度 4:报警

- 设备 FB 报警号约定 **0 = 无报警**——全套归集的前提,逐个设备输出侧确认;
- 分区/整机汇总位**每周期先清零再扫描**(无锁存),锁存版需要额外复位通道,容易与 HMI 确认逻辑打架;
- 布尔打包(Struct→Word)集中在采集层一次做,设备层只管报警号,职责不混;
- 报警区间(A 区 1..100 之类)是 HMI 约定,PLC 侧分区扫描与 HMI 解析两处一致;
- FOR 循环上界写常量:加设备「改个数」一处改。

## 维度 5:掉电保持与上电行为

- 逐变量分类:**跨周期记忆**(计数/锁存/状态机)有明确复位条件 vs **每周期重算**(Ready/Start/汇总位)在程序体开头显式赋初值——混淆这两类是复位不掉/上电乱动的根因;
- 上电首扫全场景推演:状态机中间态、门开态、定时器未完成态,各有明确去向;
- 需要掉电保持的量(RETAIN)清单化,并确认 matiec/OpenPLC 仿真轨无等价物(语义差,真机为准);
- 延时值/阈值进参数数组或命名常量,不散落字面量(现场改参不改程序)。

## 维度 6:注释与文档完备性

- 每个块头部注释:用途 / 接口假设 / 依赖的 DB 与信号;
- 魔法数有命名常量或行内注释(阈值、延时、地址区间);
- 关键条件链(Ready 链、允许链)逐行注释信号来源;
- 接口契约表(方向/名称/类型/约定)与代码同步——改代码不改契约表 = 文档撒谎。

## 输出:结构化检查报告

```markdown
# 投产检查报告 — <工程/程序名>

- 评审对象:<文件/块清单> · 验证信封 stHash:<hash> · 日期:<date>

| 维度 | 检查项 | 结论 | 证据(文件:行/块名) | 分级 |
|---|---|---|---|---|
| 互锁 | 安全门双反馈合成 | ✗ 只读了一根线 | safety_door.st:17 | 必修 |
| 报警 | 分区汇总无锁存 | ✓ | alarm_collect.st:35-47 | — |

## 必修项(投产前必须处理)
1. ...

## 建议项
1. ...

## 未覆盖/存疑
- <如实标注:哪些工况没验证、哪些判断依据不足>

评审结论:通过 / 有条件通过(必修项清零后) / 不通过
```

**纪律**:结论必须带证据定位;「通过」只对你实际看过的代码说;没验的不写通过。
